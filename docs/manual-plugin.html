SITIOO MIGRATION · 0.2.0-beta.2 · FORMATO 1

Manual del plugin

Importa una copia creada por SITIOO y recupera el destino si la migración se interrumpe.

La importación sustituye contenido del destino. Haz una copia independiente de ese WordPress antes de confirmar. Utiliza únicamente paquetes propios o de confianza: pueden contener código de temas y plugins.

1. Qué hace cada herramienta

En SITIOOEn WordPress, con el plugin
Crear el sitio local, iniciar y detener sus componentes, guardar accesos cifrados, crear copias numeradas y exportarlas.Subir y comprobar los paquetes, adaptar el dominio, importar el contenido, consultar el avance y recuperar el estado anterior de una migración.

El plugin no crea copias autónomas del hosting. Su recuperación corresponde a la migración iniciada en ese destino.

2. Requisitos y límites

  • WordPress individual 6.0 o posterior, con tablas propias de usuarios. El destino debe tener una versión igual o posterior a la que figura en la copia; las copias de esta beta parten de WordPress 7.1.3.
  • PHP 8.1 o posterior, de 64 bits para archivos grandes, con ZipArchive; MySQL o MariaDB compatible con InnoDB y permisos para crear y renombrar tablas.
  • Administrador con permisos para gestionar opciones e instalar plugins.
  • Carpeta privada escribible fuera de la raíz pública del sitio. En Linux/macOS se exigen permisos privados. En Windows x64 se requieren además mbstring y proc_open; el ZIP incluye el ayudante nativo que aplica y comprueba los permisos de Windows.
  • Espacio para los paquetes, archivos preparados y originales. La comprobación exige más de tres veces el tamaño conjunto de datos comprimidos y expandidos, más 100 MB, en la carpeta privada, y espacio adicional en el contenido.
  • Hasta 20 GB en la suma comprobada de paquetes y datos expandidos; archivos individuales de hasta 2 GB; bloques de 4 MB. Son límites del formato, no una prueba de carga de 20 GB.

La beta rechaza Multisite, tablas externas de usuarios, enlaces simbólicos, determinadas restricciones o particiones SQL, columnas generadas, serializaciones personalizadas y nombres que Windows no puede representar. El informe identifica las versiones realmente probadas; declarar una versión mínima no equivale a haber probado todas sus combinaciones.

3. Instalar el ZIP independiente

  1. Descarga sitioo-migration-0.2.0-beta.2.zip de la entrega o guárdalo desde SITIOO.
  2. En el WordPress de destino, abre Plugins → Añadir plugin → Subir plugin.
  3. Selecciona el ZIP, instálalo y pulsa Activar.
  4. Abre Herramientas → SITIOO Migration.

El ZIP es independiente de GitHub. En los WordPress nuevos creados por SITIOO ya viene instalado y activado. Para actualizarlo en un hosting, conserva antes una copia del plugin y del sitio, revisa la versión y confirma la sustitución desde WordPress. SITIOO añade una comprobación de versiones conocidas para sus proyectos locales.

4. Preparar la copia y el dominio

En SITIOO abre Copias y migración, crea una copia y expórtala. Reúne el archivo sitioo-manifest.json y todos sus ZIP de datos. El ZIP que instala el plugin se utiliza en el paso anterior y no es un paquete de contenido.

Configura primero el WordPress de destino con su dominio y protocolo correctos, por ejemplo una dirección HTTPS. El plugin muestra ese destino antes de confirmar y adapta las direcciones del origen a él. No registra dominios, modifica DNS ni configura certificados HTTPS. En local puedes importar en otro proyecto de SITIOO.

5. Subir, comprobar e importar

  1. En la pantalla del plugin, selecciona juntos el manifiesto y todos los ZIP de datos.
  2. Pulsa Subir y comprobar paquetes. La subida se divide en fragmentos y verifica tamaños y sumas de integridad.
  3. Revisa el origen, el destino y el resultado de las comprobaciones. Los errores se muestran antes de publicar la base de datos importada.
  4. Pulsa Confirmar e importar en este destino cuando estés preparado para sustituir su contenido.
  5. Espera a que aparezca Contenido importado. Durante la aplicación, la web muestra un aviso temporal de mantenimiento.

Se conservan el administrador del destino y su acceso, el dominio, la configuración del servidor y su archivo wp-config.php. Los datos de la copia se importan por bloques. El tema de la copia se conserva y los plugins importados quedan inactivos hasta que revises su compatibilidad; SITIOO Migration permanece activo.

Comprueba portada, páginas, imágenes, enlaces, datos y panel de administración. Revisa formularios, correo, pagos, licencias, cachés y servicios externos antes de poner la web en uso. Los archivos que solo existían en el destino no se eliminan automáticamente.

6. Si se corta la subida o se cierra el navegador

  1. Vuelve a entrar con el mismo administrador del destino.
  2. Abre Herramientas → SITIOO Migration.
  3. Pulsa Consultar o continuar.
  4. Si pide archivos pendientes, vuelve a seleccionar exactamente el mismo manifiesto y los mismos ZIP. El plugin retoma los fragmentos conservados.
  5. Si la sesión ha caducado, recarga la página y vuelve a consultar. No inicies otra migración mientras esta siga pendiente.

La recuperación necesita la carpeta privada y las tablas que conserva el plugin. No las limpies ni cambies de administrador a mitad del proceso. El plugin comprueba cada paquete; si uno está dañado, vuelve a obtenerlo de la copia original.

7. Recuperar el estado anterior

Si decides deshacer la migración, pulsa Recuperar el estado anterior y confirma. El plugin devuelve las tablas y los archivos que había conservado, y retira los archivos añadidos por esa migración. Deja terminar el proceso. Si se interrumpe, vuelve a la misma pantalla y continúa.

La recuperación puede sustituir los cambios que hayas hecho después de importar. Corresponde a esa migración concreta y no sustituye una copia independiente del hosting.

La beta conserva los originales de recuperación y no incorpora una limpieza automática. Si inicia una migración posterior, la pantalla pasa a controlar esa nueva operación. Conserva una copia externa antes de avanzar.

8. Carpeta privada y errores de permisos

En SITIOO, la carpeta privada se prepara automáticamente fuera de WordPress. En un hosting se utiliza una carpeta temporal privada; si no es segura o está dentro de la raíz pública, el plugin detiene la operación. Un administrador técnico puede definir SITIOO_PRIVATE_DIR en la configuración de WordPress apuntando a una carpeta privada adecuada.

En Windows, si falta el ayudante nativo, proc_open está deshabilitado o no se pueden aplicar permisos seguros, se muestra un error. No existe una alternativa silenciosa con permisos abiertos. Los paquetes importados y la recuperación contienen datos privados; mantén protegida esa carpeta.

9. Actualizar o desinstalar

Termina o recupera cualquier migración pendiente antes de actualizar o desactivar el plugin. Conserva una copia del sitio y revisa las notas de la nueva versión. Al desinstalar el plugin desde WordPress se retiran sus archivos; las tablas y la carpeta privada de recuperación no se limpian automáticamente en esta beta. Conserva esas copias hasta comprobar el resultado.

Para volver a acceder a una migración conservada, reinstala una versión compatible del plugin, usa el mismo WordPress y administrador y mantén la misma carpeta privada. No se ha implementado una búsqueda automática de recuperaciones trasladadas a otro servidor.
